# wuwa-blocks-bot

《鸣潮》3.8 版本「拉海洛方块 · 逆转」活动的本地自动游玩脚本与透明提示层。你负责选关，它负责把关打完。

全程在本机运行：通过 `PrintWindow` 截取游戏窗口、OpenCV 颜色与形态分析识别 8×8 棋盘与右侧 1～3 槽方块形状、全排列加 4 方向旋转集束搜索（Beam Search）计算最优落点，再模拟鼠标拖放与旋转。**不联网，不调用任何 AI 模型或服务，也不读写游戏内存。**

> 非官方的第三方工具，与库洛游戏无关。自动化输入可能违反游戏用户协议，使用风险自负；若重视安全，可改用完全不发送任何键鼠输入的透明提示层（`run_overlay.bat`）。

## 实测成绩

- **第 1 关（积分模式，目标 3500 分）**：全自动零失误通关，开局自动顺转 270° 触发四消（+1500），通关后于领奖画面自动停手待命。
- **第 2 关（数据损坏方块 + 3 槽布局）**：完整识别 4 角落不可消除的灰色损坏方块与 1×5 长条等 3 槽方块，单轮规划三消（+1000）并自动旋转 90° 落位。

## 环境要求

- Windows 10 / 11，游戏窗口化（推荐 1280×720，其他 16:9 分辨率按高度自动等比缩放）
- Python 3.10+，安装依赖：

```bash
pip install -r requirements.txt
```

## 快速使用

| 启动文件 | 模式 | 说明 |
|---|---|---|
| 双击 `run.bat` | **前景自动游玩（默认）** | 弹 UAC 选「是」后切回游戏选关即自动开打；`Alt+Tab` 切离游戏立即暂停、绝不抢鼠标；按 **`F8`** 随时结束 |
| 双击 `run_bg_idle.bat` | 背景停手自动模式 | 游戏可放背景被其他窗口遮住（不可最小化）；检测到你移动鼠标立即让权，停手满 2 秒后自动后台续打并还原光标 |
| 双击 `run_overlay.bat` | 透明提示层（零输入） | 在游戏上叠加点击穿透的红/橘/青步数落点框与旋转角度提示，完全不发送任何键鼠事件 |
| 双击 `run_dry.bat` | 离线干跑测试 | 截一次图并打印棋盘、方块与最优解，自动打开标注预览图 `preview.png`，不动鼠标 |

### 命令行选项

```bash
python bot.py                  # 前景自动游玩（按 F8 结束）
python bot.py --dry            # 只读盘求解并输出 preview.png
python bot.py --moves 2        # 只放 2 块就停（适合测试）
python bot.py --bg --idle 2.0  # 背景停手自动模式
python bot.py --overlay        # 启动零输入点击穿透覆盖层
python bot.py --rotate r       # 切换旋转键（游戏实测支持 rmb 右键与 r 键）
python bot.py --no-rotate      # 停用旋转
```

## 工作原理

| 文件 | 作用 |
|---|---|
| `win.py` | 查找 `Client-Win64-Shipping.exe` 游戏窗口与高 DPI 客户区坐标 |
| `capture.py` | `PrintWindow` 窗口截图（支持背景抓取）与 `mss` 备援 |
| `vision.py` | 8×8 棋盘格分类（空 / 普通 / 灰色数据损坏 / 故障晶体方块）＋ 炸弹 / 奖章图标识别、动态 1～3 槽检测、任意多联骨牌形状解码、关卡画面检测（自动排除教学弹窗与结算页） |
| `solver.py` | 整轮 2～3 块全排列 + 4 方向顺时针旋转搜索、多行连消计分、数据损坏方块保留模拟、故障方块降层优先、炸弹连锁爆炸、奖章收集优先、孤立 1×1 空洞惩罚与防死锁存活 |
| `inputs.py` | 前景 `SetCursorPos + SendInput` 拖放与背景 `PostMessage` 拖放引擎 |
| `overlay.py` | 透明点击穿透视觉提示层 |
| `bot.py` | 主循环、状态稳定确认、落点变更验证、失败重试、鼠标停手让权与 `F8` 急停 |
| `config.json` | 输入模式、旋转按键、偏移修正与时序参数 |
| `test_solver.py` / `test_vision.py` | 离线单元测试 |

## 实测得到的游戏行为

- **PC 旋转按键**：拖动方块时游戏提示「鼠标右键 / R 旋转」，每次顺时针转 90°；放回右侧槽后旋转朝向会保留。
- **落点偏移**：拖动时鼠标指针正对目标放置区域外接矩形中心（实测误差 < 1px，`drag_offset = (0, 0)`）。
- **计分规则**：单次同时消除 1 / 2 / 3 / 4 / 5 行或列分别对应 +200 / +500 / +1000 / +1500 / +2500 分。
- **特殊方块**：灰色「数据损坏方块」所在行/列填满时其余方块正常消除，损坏方块留在原位；「1/2 级故障方块」需先消除 1～2 次解除故障后方可消除。
- **炸弹方块**：无角炸弹被消除时连同周围 8 格（3×3）一起消除；有角炸弹连同周围 24 格（5×5）。故障方块上的炸弹要先解除故障才可引爆。
- **晶体覆盖（故障方块）**：被消除时不会消失，而是变回普通方块（1 级 1 次、2 级 2 次）。
- **收集奖章模式**：方块上带有奖章图标（不是普通标志）时，关卡目标是消除指定数量的奖章，达标即通关，无分数要求。左上角显示各奖章进度（如 0/10）。

### 识别与求解的处理方式（v2）

| 元素 | 识别特征（`vision.tile_features`） | 求解器处理 |
|---|---|---|
| 晶体 / 故障方块 | 方块外环「白度」标准差 > 28（晶体 32～55，平滑方块 ≤ 23） | 消除一次变普通方块 |
| 无角炸弹 `b` | 中央白色圆形占比 > 0.30，上方两角平滑 | 消除时连同 3×3 一起消除，可连锁 |
| 有角炸弹 `B` | 同上，且上方两角有尖刺（梯度 > 25） | 消除时连同 5×5 一起消除，可连锁 |
| 奖章 `m` | 中央白色图示占比 0.03～0.30 | 方块真正消失才计 1 枚，排序权重 60（高于剥晶体的 28） |
| 托盘方块上的奖章 | 逐个小格检测白色图示 | 跟随旋转，落子后视作奖章 |

尚未实机验证的假设（如与游戏不符，请修改 `solver.apply_move_ex` / `_blast`）：
- 爆炸范围内的晶体只剥一层，灰色数据损坏方块不受爆炸影响；同一步里，一个格被行消除和爆炸同时命中时，只计一次。
- 被爆炸波及的炸弹会连锁引爆，被炸掉的奖章同样计入收集数量。
- 晶体下面的图示（奖章或炸弹）不作识别，待晶体剥掉后重新截图再读；1 级和 2 级晶体暂不区分，一律按 1 级处理。
- 托盘方块上的图示一律当作奖章处理（小图难以区分是炸弹还是奖章）。

- **为什么背景拖动仍会短暂借用光标**：UE4 的 `WM_MOUSEMOVE` 不使用消息内坐标而是调用 `GetCursorPos()`，在不修改游戏内存的前提下无法绕过系统光标；故默认使用切窗即停的前景模式，并提供停手让权模式与零输入覆盖层。
